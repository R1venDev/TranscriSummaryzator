# Стадия S1E: извлечение содержания до сравнения с конспектом

## Задача

Извлеки значимые смыслы всех CORE U-ID. CONTEXT нужен для понимания связей; его реплики не становятся вторым core. Черновик конспекта тебе не предоставлен.

Создавай SourceUnit только для содержаний, которые полезно сохранить в подробном техническом конспекте: действия и обязательства, предложения, принятые решения и причины, технические объяснения, наблюдаемые результаты, ограничения, критерии, условия, альтернативы, существенные числовые сведения, вопросы, риски и поправки. Сохраняй содержательный пример, когда без него меняется смысл правила. Не объявляй привычные темы несущественными только потому, что они повторяются.

Единица должна оставаться самостоятельной по смыслу. Отрицание, условие, субъект и объект не отрываются от утверждения. Разделяй действительно разные действия, а не каждое существительное. Для unit добавь точные Evidence и только применимые существенные facets. Не строи комбинации связей всех единиц со всеми.

Короткий ответ может быть принятием, отрицанием или поправкой — не исключай его как filler автоматически. Если смысл зависит от другого эпизода, сохрани локально подтверждённую часть и open_link; не угадывай продолжение. Если в твоём CONTEXT видно однозначное уточнение core-утверждения, сохрани обе опоры и отношение.

source_accounting должен включить каждый переданный core U-ID. Смысл из нескольких реплик может иметь несколько ссылок; одна реплика — несколько units. Отсутствие извлечённых units у фрагмента не является ошибкой, если он действительно не содержит значимого содержания и accounting это объясняет.

## Вход

CORE_SOURCE, CONTEXT_BEFORE, CONTEXT_AFTER, SPEAKERS, EXPECTED_CORE_IDS.

## Выход

InventoryReport: evidence, units, source_accounting, open_links, unprocessed_ids, complete. Не создавай итоговый summary, task UUID, model-quality score или рекомендации по исправлению неназванного черновика.
