# Стадия S5: минимальное исправление

## Задача

Подготовь один набор минимальных patch bundles для конкретных FINDINGS. SOURCE остаётся авторитетным относительно сказанного; DRAFT и FINDINGS могут ошибаться. Если finding не поддержан источником, оставь его unresolved или отклони, не выдумывая исправление.

Меняй только поля и элементы, необходимые для устранения подтверждаемого дефекта. Сохраняй незатронутые подробности, правильные ссылки, стиль и структуру. Не переписывай полный документ. Не добавляй исполняемый код, shell, свободные JSON paths вне разрешённого контракта.

Для пропуска добавь достаточное содержание в подходящий существующий раздел или task card. Для ясного действия без исполнителя создай полноценную unassigned-карточку. Сроки, приоритеты, исполнители, acceptance criteria и новые подзадачи не придумываются. Для неоднозначного поля сохрани исходно названное значение/имя как неопределённое; не стирай остальные ясные части задачи.

Существующая task identity сохраняется при исправлении текста. Split/merge возможен только в явно связанном bundle по подтверждённым разным/одинаковым действиям, с lineage; вариант OR одного результата не превращается в две обязательные задачи. Не повышай предложение/возможность до принятого обязательства.

Поправка действующего технического утверждения должна затронуть все его противоречащие отображения, перечисленные в AFFECTED_SURFACES. Историческое изложение прежней позиции можно оставить, только явно обозначив последующее исправление. Сохраняй причины, важные оговорки, числа/единицы и технический scope.

Каждый bundle содержит source evidence, finding IDs, все операции и что именно должно сохраниться. Зависимые изменения объединяются либо явно указывают dependency. Не объявляй новое содержание подтверждённым: это кандидат на последующую проверку.

## Вход

DRAFT, SOURCE_CONTEXT, FINDINGS, RELATION_RESOLUTIONS, AFFECTED_SURFACES, ALLOWED_OPERATIONS, TASK_SCHEMA_DESCRIPTION.

## Выход

PatchPlan. App-generated hashes и permanent IDs не вычисляй. Для findings без надёжного исправления — unresolved. Не добавляй «улучшения» помимо исправляемой проблемы.

SOURCE_EVIDENCE — проверенные координаты цитат, на которые ссылаются findings. Они позволяют разрешить IDs, но не делают смысл замечания доказанным. Проверь его по SOURCE_CONTEXT. В evidence_ids bundle используй точные предоставленные IDs. Каждый finding должен оказаться ровно один раз в bundle, unresolved либо unprocessed_finding_ids. Не оставляй подтверждённое существенное замечание без операции только из-за неполноты другой проверки.
