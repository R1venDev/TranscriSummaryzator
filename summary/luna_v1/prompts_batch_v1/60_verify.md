# Стадия S6: проверка предложенных изменений

## Задача

Оцени каждый PATCH_BUNDLE независимо от уверенности автора или судьи. INPUT содержит старый документ, временную версию, точный diff и исходные реплики с контекстом. Не принимай исправление по наличию корректного JSON или по согласию предыдущих стадий.

Для каждого bundle установи: исправляет ли он заявленную проблему; каждое новое утверждение поддержано ли SOURCE; не удалено ли ранее верное содержание; не усилены ли актор, обязательство, условие, число или порядок; сохранены ли правильные связи и task identity; обновлены ли все нужные представления того же смысла.

Сверяй полный смысл изменённых surfaces, а не только новые слова. Если изменение создаёт противоречие с неизменённой частью документа, отметь регрессию. Для split/merge проверь самостоятельность действий, альтернативы, lineage и сохранение всех полезных полей. Необязательные null-поля не считаются дефектом сами по себе.

Если bundle правильный полностью — accept. Если содержит ошибку или потерю — reject с конкретной ссылкой. Если контекст не позволяет надёжно решить — unresolved. Зависимые операции нельзя одобрять по отдельности так, чтобы результат стал внутренне противоречивым.

Новую обнаруженную проблему опиши в new_findings, но не предлагай новую редакцию и не запускай следующий круг. Для неё укажи проверяемые source evidence ID из bundle_checks; evidence ID должны быть уникальны во всём ответе. Отсутствие замечаний по bundle не означает полную оценку всей встречи. Не выдавай обобщённый PASS вместо результатов каждого assigned bundle.

## Вход

ORIGINAL_DRAFT, CANDIDATE_DOCUMENT, PATCH_BUNDLES, EXACT_DIFF, SOURCE_CONTEXT, EXPECTED_BUNDLE_IDS.

## Выход

VerificationReport с accept/reject/unresolved для каждого bundle, source evidence и короткой причиной; unprocessed_bundle_ids для непроверенного.
