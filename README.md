# TranscriSummaryzator

Локальный pipeline для расшифровки встреч, определения говорящих и создания проверяемого саммари с таймкодами.

## Возможности

- извлечение аудио и распознавание русской речи через GigaAM;
- диаризация и сопоставление участников с голосовыми профилями;
- перенос неопределённости ASR и говорящего до итогового документа;
- evidence-first саммари: каждый факт хранит подтверждающие реплики и таймкод;
- отдельные структурированные решения, задачи, исполнители, сроки, условия и гипотезы;
- заголовок и подробное содержание задач с независимой смысловой проверкой;
- каскад моделей Ollama: извлечение, аудит критичных и публичных утверждений;
- атомарная публикация: неготовый результат не заменяет предыдущую версию;
- веб-интерфейс для загрузки записей, просмотра транскрипции и саммари;
- эталонные проверки текста, говорящих и смысла раздельно.

## Структура

- `pipeline.py` — очередь, этапы обработки и HTTP-интерфейс;
- `scripts/` — ASR, диаризация, идентификация голосов, consensus и summary;
- `tests/` — модульные проверки и проверки целостности;
- `benchmark/` — формат эталонного набора и оценка качества;
- `dashboard.html`, `profiles.html` — интерфейс;
- `deploy/linux/` — пример systemd-конфигурации;
- `macos/`, `uploader.py`, `launchd/` — отправка записей с macOS;
- `ARCHITECTURE.md` — подробная архитектура и защитные барьеры.

## Быстрый старт

1. Установите `ffmpeg`, Python и Ollama. Для GPU-сборки потребуются совместимые CUDA и PyTorch.
2. Скопируйте `config.example.json` в `config.json` и настройте модели и устройства.
3. Запустите `./install.sh`.
4. Проверьте окружение командой `./meeting-transcript doctor`.
5. Запустите обработчик: `./meeting-transcript watch`.

Файлы встреч помещаются в `inbox/`; результаты появляются в `outputs/`. Эти каталоги, голосовые образцы, локальные базы и конфигурация исключены из Git.

## Проверка

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

Текущая версия проходит автоматические проверки на Linux перед развёртыванием.

## Диагностический пакет

Каждая новая обработка создаёт append-only `diagnostics.jsonl` и компактный
`diagnostics_summary.json`. Их можно скачать кнопкой «Диагностика» со страницы
расшифровки или «Подробная диагностика» со страницы саммари.

Одна строка JSONL соответствует одному наблюдению или решению и содержит:

- компонент, этап, UTC-время, `run_id` и `job_id`;
- измеренные показатели и использованные пороги;
- выбранный результат, альтернативы и машинно-читаемые причины;
- ссылки на `word_id`, `evidence_id`, `fact_id`, claim/relation и артефакты;
- длительность модельных и системных операций;
- тип и сообщение ошибки при сбое.

Журнал охватывает VAD и ASR-чанки, обе диаризации и их consensus, Voice-ID,
кэши этапов, evidence repair, адаптивный compute, все LLM-вызовы и повторы,
проверку каждого факта, canonical `MeetingState`, provenance/coverage gates и
публикацию. Секреты по ключам `token`, `password`, `secret`, `authorization`,
`cookie` и `api_key` автоматически заменяются на `[REDACTED]`.
