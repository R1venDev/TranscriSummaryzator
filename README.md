# TranscriSummaryzator

Кодовая база расшифровывает встречи локально. В `main` также есть отдельный summary-only путь `openai/gpt-6-luna:batch` через OpenRouter: он начинает с уже готового `transcript.json` и не запускает ASR или диаризацию повторно. В примерной конфигурации он выключен (`summary_backend: legacy_local`).

## Состояние установки на 2026-09-26

- Работающая речевая служба на Linux использует отдельный release `/mnt/shared-data/MeetingTranscript` с legacy summary. У этого runtime есть серверные изменения поверх commit `87adbbe`; сам по себе `main` не доказывает, что они развёрнуты.
- Удаление terminal legacy-записей работает через отдельный `record_dashboard_wrapper.py` и dashboard в серверной конфигурации. Luna-связанные записи эта обёртка пока защищённо отклоняет (HTTP 409); совместное включение требует отдельной проверки.
- Luna Batch запущен только в изолированном release `/mnt/shared-data/transcri-work/summary-luna-openrouter` на commit `4ada035`. Синтетический платный smoke был принят; для полной частной стенограммы на последнем зафиксированном checkpoint был зарегистрирован Batch. Его итог и качество полного конспекта нельзя считать подтверждёнными без terminal raw/usage и проверки содержания. Production на Luna не переключён.

[Текущая архитектура и границы deployment](ARCHITECTURE.md) отделяют эти контуры. [Summary-only Batch](docs/SUMMARY_LUNA_BATCH.md) описывает контракт, разрешённое хранение и бюджет; [управление ключами](docs/SUMMARY_ADMIN_KEYS.md) — защищённый интерфейс. В `main` код новых функций не включает их автоматически в работающей службе.

## Возможности legacy-релиза

- извлечение аудио и распознавание русской речи через GigaAM;
- диаризация и сопоставление участников с голосовыми профилями;
- перенос неопределённости ASR и говорящего до итогового документа;
- evidence-first саммари: каждый факт хранит подтверждающие реплики и таймкод;
- отдельные структурированные решения, задачи, исполнители, сроки, условия и гипотезы;
- заголовок и подробное содержание задач с независимой смысловой проверкой;
- каскад моделей Ollama: извлечение, аудит критичных и публичных утверждений;
- атомарная публикация: неготовый результат не заменяет предыдущую версию;
- веб-интерфейс для загрузки записей, просмотра транскрипции и саммари;
- эталонные проверки текста, говорящих и смысла раздельно.

## Быстрый старт для новой установки

Эти шаги относятся к новой изолированной установке. На работающем Linux не запускайте общий установщик ради summary: он может изменить речевые окружения. Для summary-only release используйте отдельный runtime по [документации Batch](docs/SUMMARY_LUNA_BATCH.md).

1. Установите `ffmpeg`, Python и Ollama. Для GPU-сборки потребуются совместимые CUDA и PyTorch.
2. Скопируйте `config.example.json` в `config.json` и настройте модели и устройства.
3. Запустите `./install.sh`.
4. Проверьте окружение командой `./meeting-transcript doctor`.
5. Запустите обработчик: `./meeting-transcript watch`.

Файлы встреч помещаются в `inbox/`; результаты появляются в `outputs/`. Эти каталоги, голосовые образцы, локальные базы и конфигурация исключены из Git.

## Проверка

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
```

Перед развёртыванием выполняйте проверки в целевом Linux runtime и сохраняйте их результат вместе с release identity. Наличие команды здесь не подтверждает прохождение тестов текущего коммита.

## Диагностический пакет

Каждая новая обработка создаёт append-only `diagnostics.jsonl` и компактный
`diagnostics_summary.json`. Их можно скачать кнопкой «Диагностика» со страницы
расшифровки или «Подробная диагностика» со страницы саммари.

Одна строка JSONL соответствует одному наблюдению или решению и содержит:

- компонент, этап, UTC-время, `run_id` и `job_id`;
- измеренные показатели и использованные пороги;
- выбранный результат, альтернативы и машинно-читаемые причины;
- ссылки на `word_id`, `evidence_id`, `fact_id`, claim/relation и артефакты;
- длительность модельных и системных операций;
- тип и сообщение ошибки при сбое.

В legacy-пути журнал охватывает VAD и ASR-чанки, обе диаризации и их consensus, Voice-ID,
кэши этапов, evidence repair, адаптивный compute, локальные LLM-вызовы и повторы,
проверку каждого факта, canonical `MeetingState`, provenance/coverage gates и
публикацию. У Luna Batch свой приватный ledger с remote job ID, raw, status и usage;
его наличие не означает публикацию поколения. Секреты по ключам `token`, `password`, `secret`, `authorization`,
`cookie` и `api_key` автоматически заменяются на `[REDACTED]`.
