# Статус реализации и границы проверки

Этот документ описывает возможности и известные ограничения исходного кода. Наличие кода в репозитории не подтверждает его развёртывание на конкретном сервере.

## Речь, конспект и установка

- Речевой pipeline и summary-only runtime можно запускать отдельно. Переключение summary release не требует пересоздания окружений распознавания и диаризации.
- Пример `config.example.json` сохраняет `legacy_local`; Docker bootstrap выбирает `luna_batch` для новой установки. Установщик по умолчанию выбирает полный профиль `--speech`; лёгкий вариант — `--summary`. Образы загружаются из GHCR, сборка checkout включается флагом `--build`.
- Docker использует отдельные тома данных и секретов. Обновление образа и миграция действующей установки требуют самостоятельной проверки и резервной копии.
- Полный речевой образ предназначен для Linux `amd64` с NVIDIA. В нём закреплены версии публичных зависимостей трёх Python-окружений и существующие изменения совместимости DiariZen. [Происхождение runtime](DOCKER_RUNTIME.md) хранится вместе с кодом.

Проверенный архив полного окружения занимает 13 508 044 288 байт и создан до финальных правок приложения. Он подтверждает сборку зависимостей и совместимость импортов; образы каждого нового коммита требуют собственной проверки. Драйвер GPU, выполнение речевых моделей и точность результата проверяются на целевом сервере. Подробности контейнерных проверок — в [DOCKER.md](DOCKER.md).

## Luna source-first

Текущая policy — `luna_batch_source_first_v2`. При K=M=3 штатный план использует 8–10 inference items; верхний предел плана — 12. Длинные источники блокируются, если нужное число пакетов превышает этот предел.

Историческая приёмка source-first выполнила восемь items и дала результат `review_incomplete`: отдельные извлечения и отчёты проверки не прошли локальную валидацию, а в черновике оставались содержательные пропуски. Такой результат не является подтверждением качества или основанием автоматически заменять проверенный пользователем конспект.

Адаптивная capacity заменяет фиксированные stage caps. Пригодные независимые findings проходят repair даже при неполной проверке других частей; явно проверенные независимые patches могут применяться без общего полного verdict. Offline replay сохранил 12 замечаний реальной записи; live исправления и качество требуют нового API-прогона. Подробности и пределы — в контракте ниже.

Известные границы:

- `review_incomplete` допускает показ пригодного исходного черновика с обозначением неполной проверки;
- без целого пригодного writer output конспект не публикуется;
- автоматическое восстановление через split/retry после ограничения длины ответа пока не реализовано;
- состояние Batch `completed` не означает, что каждый item завершился успешно;
- неизвестный результат create POST требует сверки с удалённым Batch, а не повторной отправки наугад;
- тесты с фиктивными ответами API не измеряют качество модели и не подтверждают доступность модели для конкретного аккаунта.

Подробный контракт и история маршрута — в [SUMMARY_LUNA_SOURCE_FIRST.md](SUMMARY_LUNA_SOURCE_FIRST.md).

## Plane

Интеграция включает защищённые настройки, ручное создание из выбранной генерации, отдельные переключатели автоматической отправки задач и гипотез, Wiki-страницу встречи и сохранённое состояние внешних отправок.

Проверки с фиктивными ответами не подтверждают права API-ключа, наличие Wiki API или совместимость конкретной версии Plane. Их проверяют после настройки экземпляра. Неизвестный результат POST оставляет `submission_unknown` и требует сверки; локальный журнал не может гарантировать exactly-once внешнего сервиса.

## История развёртывания

Закрытые эксперименты Gemini и Opus и их публичные commit ID перечислены в [CHANGELOG.md](../CHANGELOG.md). Они сохраняют историю исследования предыдущих маршрутов.

Предыдущий README содержал сведения о конкретной Linux-установке и её изолированных приёмочных запусках. Эти сведения относились к отдельным release checkout и сервисам, а не ко всем установкам репозитория. Речевая служба и summary scheduler могли использовать разные версии. Для собственного развёртывания фиксируйте commit, конфигурацию, результаты тестов и используемые сервисы рядом с release.

Отдельная обёртка удаления legacy-записей `record_dashboard_wrapper.py` ранее отклоняла Luna-записи с HTTP 409. Её совместимость с вашим summary runtime следует проверять отдельно; наличие обёртки в дереве не включает её автоматически.
