# Plane: подключение, отправка и восстановление

Интеграция связывает опубликованный конспект с задачами и Wiki в указанном экземпляре Plane. Задачи и гипотезы управляются отдельно. Гипотеза остаётся предложением для проверки; отсутствие исполнителя не мешает создать задачу.

## Подключение

1. Откройте `/plane-settings` и войдите как администратор приложения.
2. Укажите базовый адрес Plane по HTTPS, slug рабочего пространства и ID проекта.
3. При необходимости укажите ID Wiki-коллекции или родительской страницы.
4. Введите API-ключ и сохраните настройки.
5. Нажмите «Проверить сохранённое подключение». Списки доступных проектов и коллекций обновляются после проверки.

Ключ хранится на сервере с шифрованием Fernet и существующим master key приложения. Он не возвращается в браузер; показана только маска. Пустое поле ключа при сохранении оставляет текущий секрет. Проверка подключения использует сохранённые значения и читает API; возможность чтения не доказывает право записи. Права записи проверяются при реальной отправке.

Backend требует HTTPS. Для доверенной внутренней сети контейнеров предусмотрено явное исключение `TRANSCRI_PLANE_ALLOW_HTTP=1`. Используйте его только для такого соединения.

Проект Plane должен иметь **пустого исполнителя по умолчанию**. Проверенная реализация Plane применяет default assignee даже при явном пустом списке исполнителей. Поэтому предварительная проверка блокирует отправку в проект с таким значением: приложение сохраняет текст исполнителя локально и не выдумывает соответствие с пользователем Plane.

## Автоматизация и ручные действия

| Опция | Начальное значение | Назначение |
|---|---|---|
| `auto_meeting_page` | `true` | Wiki-страница для нового опубликованного конспекта после настройки подключения |
| `auto_tasks` | `false` | Автоматическое создание задач |
| `auto_hypotheses` | `false` | Автоматическая отправка гипотез как предложений |

Существующие поколения конспекта фиксируются как исходное состояние при подключении. Включение интеграции не запускает автоматическую отправку всей истории. Для существующей встречи используйте ручное действие в конспекте, включая «Создать страницу встречи».

Кнопки работают с конкретной генерацией конспекта и ID пункта. Если отображаемая генерация устарела, страницу нужно обновить. Если карточка отредактирована, сначала сохраните изменения. Связь с удалённой задачей хранится локально; повторное действие не создаёт новый объект для уже связанного пункта.

Автоматические настройки независимы: можно отправлять Wiki автоматически, а задачи и гипотезы выбирать вручную.

## Изменения и повторная генерация

Идентификаторы задач принадлежат приложению. При повторной генерации уже созданные удалённые объекты сохраняются. Обнаруженные изменения помечаются как `update_available`; содержимое Plane не перезаписывается автоматически, чтобы сохранить ручные правки.

Сопоставление гипотез использует локальные правила идентичности. Если соответствие неоднозначно, отправка блокируется состоянием `identity_ambiguous` до разрешения неоднозначности. Новые однозначные пункты можно создавать как обычно.

Смена проекта, workspace или другого назначения не перенаправляет уже сохранённые отправки. Перед отправкой назначения сверяются с сохранённым намерением.

## Состояния и неизвестный ответ

| Состояние | Что означает |
|---|---|
| `not_created` | Объект ещё не создан; доступно ручное действие |
| `queued` / `sending` | Отправка ожидает выполнения или уже выполняется |
| `created` | Сохранена связь с созданным объектом Plane |
| `update_available` | Локальный материал изменился; удалённое содержимое сохранено |
| `failed` | Операция завершилась известной ошибкой; доступен ручной повтор |
| `submission_unknown` | Результат POST неизвестен; новый create запрещён до сверки |
| `unconfigured` / `blocked` | Требуется настройка подключения или устранение причины блокировки |
| `identity_ambiguous` | Нельзя однозначно сопоставить пункт с существующим объектом |

Перед POST приложение сохраняет намерение отправки. Если ответ потерян или соединение оборвалось, повторная попытка создания не выполняется вслепую. Восстановление использует GET и ищет объект по внешнему ID карточки либо по точному маркеру страницы. Подтверждённый объект связывается с локальным пунктом. Неопределённый результат остаётся `submission_unknown`.

Это защита от повторного POST при восстановлении. Локальный журнал не может гарантировать exactly-once поведение стороннего API.

## Совместимость и данные

Интеграция использует API v1 work items и Wiki-страниц рабочего пространства. Контракт ориентирован на установленный Plane 3.1.0; другая версия, редакция или набор прав могут ограничивать доступ к страницам и коллекциям. Ошибка Wiki не должна трактоваться как успешное создание страницы.

Plane получает отправляемое содержимое конспекта, карточек или гипотез. Выбранные URL, workspace и проект определяют назначение данных. Тесты с фиктивными ответами проверяют механизм и восстановление; реальные права ключа и работу вашей версии Plane проверяют отдельно.

## API и проверка совместимости

Проверено по официальным [страницам API](https://developers.plane.so/api-reference/page/add-workspace-page),
[аутентификации](https://developers.plane.so/api-reference/introduction) и исходникам
установленной версии 3.1.0 (2026-10-02). API-пути проверены отдельно от UI-ссылок.
Создание страницы использует `description_html`; полный текст раскрываемых деталей
включается в совместимые HTML-блоки, поскольку поддержка disclosure в редакторах
Plane различается. В приложении и скачанном HTML раскрытие остаётся доступным.
Видео не копируется в Plane автоматически: сохраняются ссылки на конспект и источник.

Персональный токен создаётся в Plane → Profile Settings → Personal Access Tokens.
Если ваша инсталляция использует workspace access tokens, используйте разрешённый
раздел Access Tokens в workspace settings. Добавьте значение только в защищённой
форме TranscriSummaryzator. Проверка соединения выполняет GET, не создаёт тестовые
задачи и не отправляет запрос в LLM. Ссылки на источник требуют доступа получателя
к вашему экземпляру TranscriSummaryzator.

## Откат

Отключите автоматизацию и остановите summary scheduler перед возвратом предыдущего
summary release. Речевую службу перезапускать не нужно. Сохраните `plane.sqlite3` и
master key: они нужны для восстановления неизвестных POST и предотвращения дублей.
Откат кода не удаляет уже созданные страницы/карточки Plane. Повторное включение
использует прежний outbox. Не очищайте его ради повторной отправки.
